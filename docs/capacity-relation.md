# Capacity-dependent bank selection

`bank::Contract` and `bank::check` describe and compare storage formats. Matching `when_one` and `otherwise` addresses does not establish that two discriminator programs return one on the same installed controller. `Checks::plan_to_with_policy` additionally requires a capacity relation under both ordinary and explicit-crossflash policies. Failure has code `pioneer.startup.capacity_relation_unproved`.

The relation is sufficient when the actual recognized address expression is independent of its discriminator, when both complete decoded components are unchanged, or when both firmwares run an identical discriminator program over identical address cases. The unchanged case compares SHA-256 identities of both actual inputs and requires a complete 64 KiB Kernel. A missing Kernel is not an identity witness. Public storage enums cannot construct positive capacity evidence. Fixed-address and older resident-owned storage retain their existing comparison behavior.

## Discriminator program digest

The program proof is derived from the two images alone with `h8-asm` — no live query and no hand-rolled instruction decoding — so the offline and online compares are equal and the proof can only under-accept.

The discriminator does not run in place. The C initializer relocates a block out of Normal into low RAM (the `0x1058dc` memcpy; on the recognized family the complete 652-byte helper block is copied to 04BA..0746) and the versioned contract calls the discriminator there (e.g. query 05A2, which calls builder 0646 and resident 107C72). `coverage::copied_checksum::relocated` recognizes that bound copy generically: it decodes the complete C initializer, tracks the memcpy argument graph (ER0 source, ER1 destination, ER2 length) through the bound copy/clear helper chain, and returns the Normal source span and its RAM destination for the single validated copy that covers a given entry. An unrecognized initializer, an unrecognized helper, or an ambiguous or partial copy refuses.

`capacity::program` rebuilds the RAM image from that source and destination so each routine decodes where it executes, then digests the transitive closure of the routines reachable from the discriminator entry *by a call within the copied block* — the query plus its builder and any other relocated callee. Each routine is bounded by `h8-asm` control-flow reachability (a gap, embedded data, or a branch that leaves the block refuses) and normalized with `relocate`: PC-relative control flow normalizes to a canonical base, an absolute branch into a routine refuses, and every other operand is retained exactly. Calls that leave the copied block — the resident OEM query/copy service — stay as retained absolute operands, not digested bodies, so a differing resident target changes the digest. A routine that decodes differently, calls a different in-block helper, or reads a different absolute datum therefore digests differently and never matches.

The installed resident query/copy interfaces and a stable completed identification result until the next command are existing OEM interface dependencies, as before: the digest preserves their uses as retained absolute operands and does not claim physical ROM, global startup termination, arbitrary hardware progress, or absence of NMI/reset/fault behavior. No saved parameter or bank migration is performed.

## Evidence and regression scope

Targeted unit tests cover the closure digest directly: identical closures digest equally and out-of-closure bytes are irrelevant (the proof scopes to the reached discriminator, not the whole block); any change inside a reached routine — an in-block callee body or a retained resident-service call target — changes the digest; and an entry outside the copied block refuses. The refactor of `copied_checksum` into a shared generic `relocated` is covered by the existing checksum and sink coverage tests. The private-corpus path exercises the relation on real firmware under both policies in CI.

Changed distinct-case routes refuse unless the discriminator program digests prove identical, even when the two case-address arrays match. This is a per-update evidence boundary that can only under-admit — a differing discriminator never relates — not a claim that all other devices or capacity queries are physically incompatible. Fixed-bank routes, actual collapsed cases and unchanged complete pairs retain their respective scopes. Startup CMP correction and other filter owners remain independent obligations.
